# 校内考试与四六级听力

听力沿用当前 App 的本地数据库、间隔复习算法、导出入口和分层架构。
原题和 AI 模拟题分别标记来源；没有答案的题不会被自动判错。

## 课程资料边界

真实课程资料由使用者在本机导入。公开仓库不包含校内 PPT/WAV、真实转录或个人答题数据。
缺少标准答案时使用 `grading: {"status":"missing"}`，原文缺失时明确标记 missing，
不能将推断当成学校标准答案或实际听力原文。

公开示例均为虚构原创内容。测试 WAV 是合成测试音，仅用于检查文件存储和播放器，不验证语言题意。

## 导入顺序

1. 准备听力材料清单，参考 `public/examples/listening-library.json`。
2. 打开“听力训练 → 导入 / 补绑听力材料”，选择清单 JSON 与 WAV（可多选）。
3. 核对每段的音轨和文件绑定。唯一且相同的文件名自动匹配；重名或不匹配时手动选择。
4. 点击“确认保存清单与选中音频”。状态区明确显示已绑定和待绑定数量。
5. 在“题包与数据”导入每日题包 v2，参考 `public/examples/listening-day.json`。
6. 返回“听力训练”开始本组。未绑定媒体的分组不能开始。

可以先保存无音频的清单，界面会标记“待绑定”。这只代表题目可建立关联，不能声称已经能播放。
以后导入相同清单补选原 WAV；已有绑定按 SHA-256 验证，不允许同一个音轨静默改绑成不同内容。
清单内容或同一题 ID 内容冲突时拒绝覆盖，保留旧学习历史。

初版 WAV 每段最多 128 MB，支持 RIFF/WAVE 单/双声道 PCM（8/16/24/32 位）及 32 位浮点。
校验容器、数据块长度和时长；浏览器播放器还要成功加载元数据，才能提交本组。
不支持的编码应另存兼容副本；不修改原文件，不自动转码。资源限制须用实际 8 段文件进一步核对。

## 题包协议

现有题包 v1 保持可用。v2 保留 `id/title/date/words/choices` 并新增 `listening`。
每个听力组有 `id/libraryId/trackId/questions`，可引用已经导入的音轨。
同一段可包含原题单选和额外模拟题，也可以只含其中一种。

| 字段                    | 约定                                                 |
| ----------------------- | ---------------------------------------------------- |
| type                    | listening-choice / listening-cloze                   |
| origin                  | course-original / chatgpt-extra                      |
| prompt                  | 题干；听写以 {{b1}} 等标记空位                       |
| options                 | 单选选项，2–8 项，选项 ID 唯一                       |
| blankIds                | 听写空位 ID，每个必须在题干出现一次                  |
| grading.status          | verified（已核对）/ draft（未核对）/ missing（缺失） |
| grading.answerId        | 有参考答案的单选题必填；必须存在于选项中             |
| grading.acceptedAnswers | 有参考答案的填空题必填；空位 ID 对应允许答案数组     |
| grading.explanation     | 有参考答案时的解析字符串                             |

missing 时 grading 只包含 status。不会自动补成 A 或把缺失答案当作错题。
听写按每个空位精确判定，沿用拼写规范化；不同拼法需明确列入 acceptedAnswers。

材料库 `target` 可用 campus、CET-4、CET-6。每单元可以包含 news-report、conversation、passage-1、passage-2。
`transcript` 也有 verified/draft/missing 三种状态；missing 的 text 为 null。
`segments` 初版可以为空，非空时验证时间范围，但本轮不实现逐句精听界面。

## 练习与复习

播放器支持进度拖动、重播、循环和 0.75/0.85/1/1.25/1.5 倍速。
记录的是播放器启动次数和提交时最后倍速，不把它冒充已听完次数。
答题草稿串行写入；整组提交成功后才显示答案、解析和原文。重新练习时再次隐藏。
参考答案已在用户自己的 JSON 中，这只是界面隐藏，不是防作弊或数据加密。

正确率按单选每题 1 分、听写每空 1 分计算；分别展示两类题得分。
缺失答案排除评分分母；全部无答案时显示“待批改”。draft 产生“暂评”并保留未核对标记。

单选题或整道填空题各有一份复习状态，身份为 `[listening, libraryId, questionId]`。
重复出现在不同日期的同一题沿用进度。错题、到期题按音轨整组练习，提前重复答对不推进阶段。
使用与旧模块相同的 nextSchedule 函数安排 1/3/7/14 天及后续间隔。
缺失答案的题保存作答，但不更新掌握度；暂评错误可以安排复习，记录上保留暂评状态。

提交后可选择错误原因并另存备注，原始作答不被重写。备注须点击“保存错误原因”。
界面展示逐题次数、累计错误、下次复习和最近 20 组记录。

## 存储与备份

数据库仍名为 `english-pocket-v1`，Dexie schema 从 1 显式升级到 2，只增加听力相关表。
浏览器音频保存在 IndexedDB Blob；Android 适配器把音频写入 App 私有 Data 目录，元数据仍在 Dexie。
Blob URL 仅在当前播放会话使用，退出后释放。真实 WAV 和 PPT 不放 public，也不推送 GitHub。

浏览器媒体和清单在同一事务发布。Android 先写临时文件并校验长度，再改名并提交数据库引用。
被中断的原生导入可能留下没有引用的文件；当前不自动删除旧文件或清空用户目录，避免误删。

- 无听力资料时，“完整备份”继续输出兼容的 v1 JSON。
- 有听力资料时，“完整备份”输出标准 ZIP STORE，包含 data.json 与 media/<SHA-256>.wav。
- “轻量进度”输出 v2 JSON，不含 WAV。换机恢复后缺失媒体明确标记待补绑。
- 恢复轻量备份会复用当前库中哈希匹配的媒体；新库可通过原 WAV 补绑。
- ZIP 校验 CRC-32、媒体大小和 SHA-256，所有检查完成后才替换数据。

仅支持本 App 导出的未压缩、未加密、无 ZIP64 的备份 ZIP，初版总上限 256 MB；不做通用压缩包导入。
JSON 数据上限 50 MB。音频缺失或超过上限时拒绝生成“完整备份”，仍可导出轻量进度并另存原 WAV。
容量上限内的备份也会暂用内存；真实手机的大文件能力仍须验证。
旧 v1 备份继续支持；恢复操作会明确确认替换，不能将新备份交给旧版本假装兼容。

结果导出仍在“题包与数据”，支持 JSON 和文本。v2 结果包含听力原始答案、题目/原文快照、
评分可信状态、播放统计、错因备注和逐题次数；不携带 WAV，不自动发送给 ChatGPT。

## 验证范围

单元/存储测试覆盖旧库升级、格式约束、坏音频、哈希去重、题目身份、事务回滚、幂等提交、
待批改分母、暂评分数、跨日期复习、备注、轻量恢复和完整 ZIP 往返。
手机尺寸 Chromium 流程覆盖真实 Blob 音频加载、倍速、循环开关、草稿跨刷新、断网重开、
提交前隐藏答案、提交后显示、错因导出，以及新上下文完整 ZIP 恢复后再练。

浏览器验证不能替代 Android 真机验证。真实 PPT/音频内容核对、Android 文件选择与播放、
大 WAV 导入、长时间后台和 APK 升级后的保留记录仍未验证。
